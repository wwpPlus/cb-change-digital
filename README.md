# cb-change-digital-变更管控数字人

需求文档

## 背景与目标

### 背景痛点

- 变更方案填写成本高、重复劳动多（同类变更反复编辑人员/设备/时间/步骤）。
- 方案质量不稳定：必填缺失、风险等级与操作等级不一致、制度条款遗漏。
- 模板沉淀困难：个人经验无法标准化共享，模板版本不可控。
- 稽核强依赖人工：耗时、尺度不一致、难以追溯。

### 建设目标（可量化）

- **效率**：基于模板+快捷编辑，将“4/5级方案”平均编制时间下降 ≥50%。
- **质量**：稽核一次通过率提升（必填缺失/不一致项降低 ≥70%）。
- **合规**：制度规则可配置、可追溯；稽核结论可解释、可复核。
- **沉淀**：方案一键生成模板（共享/个人），形成持续迭代的模板库。

## 范围与边界

### 本期范围（MVP）

1. 模板库筛选（专业/子专业/共享/个人）+ 查询
2. 基于模板快速编辑（你列出的：名称、人员、设备、时间、范围…且支持扩展到更多字段）
3. 发起申请 + 方案稽核（规则校验 + AI 辅助）
4. 模板的增删改查（共享模板与个人模板）
5. 根据方案生成模板（共享/个人）

## 术语与分级

- **变更方案**：一次实际变更的方案实例（可从模板生成、可转为模板）。
- **变更模板**：可复用的方案基线（共享/个人），可版本化。
- **4级方案结构**：概述/准备/步骤/后工作/舆情（详见后面的字段）
- **5级方案结构**：简化结构（小组/资质/方式/步骤/测试/倒回）
- **风险等级**：制度定义（一般与客户影响/中断/安全等关联）
- **变更操作等级**：制度定义（一般与操作方式、对象范围、复杂度关联）
- **五级白名单**：对风险5（或制度高等级）操作的预授权条目（按场景/对象/操作内容匹配）

## 核心业务流程

### 方案创建主流程（模板驱动）

1. 用户选择【专业/子专业】→ 筛选模板（共享/个人）
2. 选中模板 → 进入【快捷编辑】
3. 快捷编辑完成 →【保存草稿】/【发起申请】
4. 发起申请触发【稽核】
5. 稽核通过 → 进入“待执行/待审批”（按你们流程定）
6. 执行后补录“操作后工作/复核结果/附件” → 关闭归档
7. 可从任意方案【生成模板】→ 进入模板库

### 稽核闭环（整改-再提交）

- 稽核不通过 → 输出“问题清单（必填缺失/冲突/制度不符/AI建议）”
- 用户按问题逐条修复 → 再次发起 → 重新稽核
- 全程留痕（每次稽核版本对比、结论、责任人、时间）

## 模板库

### 筛选与搜索

- 过滤条件：
  - 专业、子专业、网元类型、场景类别
  - 风险等级、变更操作等级
  - 模板类型：共享模板 / 个人模板
  - 关键词：模板名称、操作内容、操作对象
- 排序：最近使用、最近更新、风险等级、收藏
- 列表展示建议字段：模板名、专业/子专业、网元类型、风险等级、操作等级、更新时间、作者、共享标识、版本号

### 模板详情查看

- 展示模板结构（4级/5级）
- 展示适用范围/注意事项/必填提示
- 支持：一键“用此模板创建方案”

### 模板维护（增删改查）

- 个人模板：创建/编辑/删除/复制
- 共享模板：仅模板管理员可编辑/发布/下线
- 模板版本：
  - 发布新版本时保留旧版本（可回滚）
  - 方案引用模板时记录模板版本号，保证可追溯

## 快捷编辑（核心）

### 默认快捷编辑项（你已定义）

1. 方案名称
2. 变更人员（含角色、单位/部门、姓名、电话）
3. 变更设备（设备名、IP）
4. 变更时间（自动生成多个时间点）
   - 割接起止：默认 00:00–06:00
   - 操作前校验完成时间：割接开始前 24h
   - 测试验证时间：割接结束后 2h
   - 变更倒回时间：割接结束后 3h
5. 操作范围（文本/多选字典/引用网元范围）

### “快捷编辑项可扩展”机制（建议落地方式）

- 系统提供【快捷编辑配置】（模板管理员可配）：
  - 可选字段：从方案结构中勾选（例如：影响范围、操作方式、关键步骤标识、倒回触发条件等）
  - 支持按“专业/子专业/等级（4/5）”配置不同快捷编辑面板
- 用户侧体验：
  - 快捷编辑=“必填+高频字段”，其他字段在“详细编辑”里完成

### 时间自动计算与校验

- 自动计算：按割接起止时间生成其它时间点，允许用户手动调整
- 校验规则：
  - 操作前校验完成 ≤ 割接开始
  - 测试验证时间 ≥ 割接结束
  - 倒回时间 ≥ 割接结束
  - 所有时间必须同一时区、格式统一
- 支持“跨天割接”场景（例如 23:00–02:00）

## 方案详细编辑（结构化）

### 方案基础信息（你提到的元信息）

- 方案id（系统生成）
- 方案名称
- 专业 / 子专业
- 网元类型
- 场景类别
- 变更操作内容
- 操作对象
- 网络操作范围
- 操作复杂程度
- 客户潜在影响
- 是否中断业务
- 业务潜在影响
- 风险等级
- 五级白名单（关联匹配结果/引用条目）
- 是否模板（bool）
- 备注/附件

> 建议：这里做成“基础信息卡片”，用于稽核与搜索索引。

### 4级方案结构（按你给的字段表格化）

每个部分都以“可增删行表格”为主，配合少量文本说明：

1）变更操作概述

- 目的和需求（目的、操作范围、操作时间、变更专区、实施物理地址、来源）
- 变更操作等级（等级、定级依据）
- 变更操作方式（方式枚举 + 原因/场景说明）
- 变更设备清单（设备名、IP）
- 影响（影响范围、业务影响、安全影响、互联互通影响）

2）变更操作准备

- 变更小组（单位、角色、姓名、电话）
- 小组资质（角色、人员类型、是否通过安全认证、其他资质）
- 工具与软件（类型、名称、责任人）
- 设备运行检查（项目、结果或步骤、责任人）
- 风险评估及应对（问题描述、可能性H/M/L、影响H/M/L、措施）
- 操作前检查（确认工作、责任人、完成时间）
- 条件检查（责任人、完成时间）
- 操作校验（校验工作、责任人、完成时间）

3）变更操作步骤

- 操作步骤（步骤、内容、实施人员、是否关键、审核人员、操作时间）
- 测试验证（测试项目、方法、责任人、时间）
- 失败倒回方案（倒回时间、倒回决策人、触发条件）
- 倒回步骤（步骤、内容、实施人员、审核人员、操作时间）
- 倒回测试（这里你原文是风险字段，建议修正为“倒回测试项目/方法/责任人/时间”，更一致）
- 倒回风险分析（风险概述、可能性、影响、措施）

4）操作后工作

- 次日保障（姓名、部门/单位、联系方式）
- 业务复核（复核项目、方法、复核时间、观察责任人）
- 其他工作（内容、责任人）

5）舆情应对方案及口径

- 次日保障（姓名、职位、联系方式）
- 口径文本/FAQ（建议加：对外口径、内部通告模板、升级联系人）

### 5级方案结构（简化）

- 变更小组名单（同4级小组表）
- 变更操作资质（同4级资质表）
- 变更操作方式（同4级方式）
- 操作步骤（同4级步骤表）
- 测试验证（同4级）
- 倒回步骤（同4级）

> 建议：5级仍保留“基础信息卡片”，否则搜索与稽核会弱。

## 方案稽核（规则 + AI）

### 稽核触发时机

- 发起申请时强制稽核
- 保存草稿可选“预稽核”（建议加，体验好）

### 规则稽核（强规则，必须落地）

A. 必填校验（按等级/专业可配置）

- 基础信息必填：专业/子专业/等级/风险/操作等级/操作内容/对象/范围
- 人员必填：关键角色（操作人、审核人…）至少各 1 人，电话格式合法
- 设备必填：设备名/IP（IP 格式校验）
- 时间必填：割接起止、校验完成、测试验证、倒回时间（并满足时序）

B. 一致性校验

- 风险等级 vs 变更操作等级：必须满足映射关系（映射表可配置）
- 是否中断业务=是 → 业务影响字段必须填写且风险不得低于某阈值（可配置）
- 操作方式=不使用4A → 必须填写原因/具体场景

C. 制度合规校验（建议以“规则引擎配置”实现）

- 例如：风险≥X 必须有倒回方案、必须有关键步骤审核人、必须有业务确认人等
- 例如：物理变更操作必须填写实施物理地址、现场配置场景说明

D. 五级白名单校验

- 当风险=5 或制度要求触发时：
  - 若命中白名单：通过但仍需提示“命中条目：xxx”
  - 未命中：必须走更高审批/强制补充材料（本期可先做“强提示+不通过”）

### AI 稽核（软规则，给建议+风险提示）

AI 输出形式建议标准化为：

- 问题列表：`{问题类型, 严重级别, 证据字段, 建议修改, 参考制度条款(可选)}`
- 覆盖点（建议先做这些）：
  - 文本字段逻辑冲突（例如：写“不中断业务”但业务影响描述很大）
  - 步骤可执行性/缺关键步骤（如缺登录、备份、回滚点）
  - 风险评估与措施是否匹配（高风险却无措施）
  - 舆情口径缺失（高等级却未填）
- AI 结论必须可复核：展示“依据字段/摘要”，避免黑盒

> 建议：最终“是否通过”仍以规则稽核为准；AI 作为补充建议/预警，降低误杀。

## 方案生成模板

- 入口：方案详情页 →【生成模板】
- 生成规则：
  - 自动抽取方案结构与字段
  - 支持勾选“去个性化”（如去除电话号码/具体姓名，仅保留角色与单位模板）
  - 选择模板归属：共享 / 个人
- 共享模板生成需权限：模板管理员审核发布（至少二次确认）

## 数据模型（落库建议，便于研发开工）

### 核心实体

- Template（模板）
- Plan（方案实例）
- PlanSection（概述/准备/步骤/后工作/舆情）
- SectionItem（各表格行项目，按表类型区分）
- PlanPerson（人员表）
- PlanDevice（设备表）
- PlanTimePoint（时间点表）
- AuditRecord（稽核记录：规则结果、AI结果、结论）
- Dictionary（专业/子专业/网元类型/场景类别/操作方式等）
- WhiteListItem（五级白名单条目）

### 方案与模板的关系

- 模板发布版本：TemplateVersion
- 方案引用：Plan.template_version_id（可为空，表示非模板创建）

### “多表格行项目”的通用建模建议

两种可选：

1. **强类型分表**（研发最舒服，查询清晰）：每个表格一张 item 表
2. **统一Item表 + JSON schema**（灵活但开发约束要做足）

如果你希望“每个表格项一个 DTO 强类型化”，推荐走 **强类型分表**（和你之前的开发偏好一致）。

## 权限、安全与审计

- 权限原则：
  - 个人模板仅本人可见（可配置共享给指定人/组作为增强）
  - 共享模板只读给普通用户
- 审计日志（必须）：
  - 方案/模板的创建、编辑、删除、发布、下线
  - 稽核触发与结论、问题清单
  - 字典/规则/白名单变更
- 数据脱敏：
  - 导出/共享时可脱敏电话等个人信息

## 非功能需求

- 性能：模板库列表查询 < 1s（常用条件下）；方案保存 < 500ms（异步也可）
- 可用性：关键链路（发起申请+稽核）可用性 ≥ 99.9%
- 并发：支持晚高峰集中提交（建议稽核异步队列 + 前端轮询/回调）
- 可靠性：草稿自动保存、防丢；稽核记录不可篡改（仅追加）
- 可配置：规则、映射表、必填项、快捷编辑字段、字典均可后台配置

## 验收标准（可直接做测试用例）

1. 模板筛选：按专业/子专业/共享类型筛选正确，排序正确
2. 快捷编辑：默认字段可编辑，时间点自动计算正确，手动修改后联动正确
3. 详细编辑：4级各表格可增删行，字段校验生效（电话/IP/时间顺序）
4. 发起申请：触发稽核，缺必填必拦截，并生成可定位的问题清单
5. 一致性校验：风险等级与操作等级不匹配时，必须阻断/要求补充依据（按配置）
6. AI 稽核：能返回建议列表，展示证据字段，不影响规则稽核判定
7. 模板维护：可发布新版本、回滚；
8. 方案生成模板：可选共享/个人；
9. 审计日志：所有关键操作可追溯到人、时间、差异内容
